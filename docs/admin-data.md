# 后台同步配置与数据迁移

在随机管理入口登录后，点击「同步与数据」。所有操作使用现有管理会话，写入与导出均检查同源 Origin 和 `X-Cerium-Admin: 1`。

## 同步周期

- 可使用秒、分钟或小时，换算后必须是整数秒；范围为 60 秒至 365 天。
- 保存到 web SQLite 的 `settings.sync_interval_seconds`，立即重新计算公开自动站点的下一次同步时间，重启仍然保留。
- `SYNC_INTERVAL_SECONDS` 默认 900，仅在数据库首次初始化该设置时提供默认值，之后不会覆盖后台保存的配置。
- 调整周期保留已等待的时间，不会从保存时重新计时；已排队、执行中和退避重试的任务不会被取消或重放。
- 隐藏站点与手动站点不自动同步；不同站点默认最多四个并发任务，同一站点保持串行及凭据租约，不承诺精确秒级刷新。前台轮询频率不受此设置影响。

编辑已有站点必须提交读取时的 `revision`。较新的配置已经保存时返回 409，编辑器保留草稿并提供显式载入最新配置的入口。名称、简介、充值与支付说明等展示字段使用独立编辑版本，不废弃正在进行的采集；身份或认证变更才推进同步版本并使旧任务过期。极端版本号在迁移时更换站点身份并保留旧身份清理任务，避免安全整数溢出或复用旧回调版本。

409 错误通过 `code` 区分 `stale_revision` 和 `duplicate_identity`。重复身份允许继续修改草稿；仅旧版本编辑需要载入最新配置。手动站点修改名称、简介、支付信息或显示状态时保留原目录时间，只有目录内容或来源身份变化才更新该时间。

启动迁移统一历史 URL 的尾斜杠与转义格式。历史非法百分号或空查询、片段分隔符会修复并暂停该站点，要求管理员核对后重新启用。规范化后身份重复时保留原顺序的主记录，其他记录保留资料与凭据并禁用；这些隔离记录仍可备份恢复，也不会阻止主记录编辑。

## JSON 与 SQLite 备份

两个格式包含相同的业务数据：所有站点（含隐藏站点）、配置与明文凭据、最后成功快照、抓取时间与诊断、动态记录及其撤下状态、同步周期，以及独立于 sync 的 favicon 候选 / 选中地址、失败状态和已缓存的图片字节。恢复已有图标缓存后不需要访问上游。
支付渠道预设也包含在两个格式中；旧备份缺少该设置时保留当前预设。

- **JSON**：版本化 `cerium-web-backup` 文件，可阅读或编辑。修改后仍须通过完整字段、公开快照、唯一身份和记录关联校验。
- **SQLite (.db)**：真正的 Cerium web SQLite 数据库，使用 SQLite backup API 生成一致性快照，包含已提交的 WAL 数据，可在运行中导出。不是 SQL 文本脚本，也不是 Go 同步器数据库。
- 不包含管理入口、管理密码、登录会话或旧同步任务。SQLite 导出还清空任务表并压缩数据库，避免这些内容残留在空闲页中。
- 文件最多 64 MiB。可在导出前取消包含图片缓存；超过上限的完整业务备份会尝试去掉可重新获取的图片缓存，并通过响应头和界面提示。站点配置、凭据、快照和动态图标地址保留。导出的账号密码、面板令牌均是明文，应当作为高权限机密保存，不要公开分享、提交到 Git 或上传到不可信服务。
- JSON 的 `favicon_cache` 保存 MIME 类型和 Base64 图像，SQLite 的 `favicon_blob` / `favicon_type` 保存对应字节与类型。单张图片最多 1 MiB，导入时同时验证图像内容和类型，无效缓存不会部分写入。
- 兼容只有图标地址或没有 favicon 字段的旧版 JSON 备份和旧 SQLite 数据库；首次请求时下载旧地址或独立发现，补齐图片缓存，不会跟随后续 sync 重新选取。
- 新编辑和同步结果拒绝同一分组内的重复模型报价；历史备份与完整恢复保留旧重复报价，详情与比较器显示无法确认单价，不任取其中一条计算费用。

所有导入导出共享维护屏障：暂停新任务调度并等待已开始的写请求、任务投递和图标发现完成。等待任务结束时继续接收其同步回调，开始读写备份后回调返回可重试的 503；新的管理写入返回 409，图标发现返回 503。读取目录和健康检查仍可用。成功或失败后解除屏障，未完成的灾难恢复仍保持暂停。

## 支付渠道与充值

后台「同步与数据」可维护支付渠道预设，每行一个，最多 32 项且每项不超过 40 个字符。默认包含云猫寄售、链动小铺、站点直充。站点表单最多多选 12 项，移除某个预设不会改写已保存站点的渠道。

充值只填写获得 1 USD 站内额度需要的 CNY 数值，不维护独立充值倍率。旧配置 `10 CNY = 20 USD` 编辑或导入后等价归一化为 `0.5 CNY = 1 USD`，不改变兑换价值；旧充值倍率字段不再返回或展示。

## 导入行为

默认使用「合并」。按站点 ID 优先匹配；没有相同 ID 时，自动站点可按 URL、类型、账号 / 用户 ID 匹配。匹配站点的配置与快照会被覆盖，未出现在备份中的站点保留，动态记录合并并保留最多 2000 条。多个导入站点映射到同一现有站点时拒绝导入，避免含糊覆盖。

「替换」以备份恢复整个目录，删除备份中不存在的站点及其动态记录。界面需要勾选确认后才允许执行，请先导出当前数据。

两种方式均采用备份中的同步周期。文件先校验再以事务写入；校验、身份冲突或写入失败会整体回滚，包括设置和队列。导入文件中的 SQLite 表结构或 SQL 不会在业务数据库中执行：文件在私有临时目录只读打开，只读取指定的普通表，拒绝视图、触发器、虚拟表和不兼容数据库。

业务导入保留当前管理入口和会话，旧任务被标记过期，新任务使用本地推进的同步版本和新任务 ID，不直接信任备份中的高版本值。公开自动站点重新排队同步；移除的站点和改成手动维护的站点排队清理 Go 同步器凭据。过期任务的迟到回调不会覆盖导入数据，原有尚未完成的删除清理任务不会被整体清空。

JSON 与 SQLite 业务备份只迁移网站目录。需要保留 Go 登录会话、AT/RT/Cookies、一次性模型探测缓存、待清理 Key 和站点版本映射时，使用下面的完整恢复入口。

## 完整恢复

「同步与数据」的完整恢复包同时保存 Web 数据库和 Go 同步器的持久状态，包括未完成任务、幂等记录、探测结果与远端 Key 清理队列。导出会暂停网站调度、等待正在执行的任务完成，再通过签名接口取得同步器快照；不会重放探测或旋转 Token。

恢复前校验格式、组件大小、SHA256、数据库结构和业务约束，再暂停调度。同步回调和其他管理写入在恢复期间返回可重试错误。Go 恢复和 Web 事务之间使用持久恢复日志：本地写入失败会回滚 Go；进程中断后先修复未完成的恢复，readiness 返回 503，完成前不恢复调度。管理入口保持当前地址，界面在恢复后要求重新登录。

恢复包是版本化 gzip 容器，包含明文敏感数据。在线路径有明确容量限制：压缩包最多 512 MiB，Web 组件最多 512 MiB，Go 组件最多 256 MiB。超过在线容量时，使用完整卷备份：先 `docker compose stop`，分别归档 `web-data` 与 `sync-data`，同时记录所用代码版本和必要运行配置；恢复时停止服务，将两个对应卷一起恢复，再 `docker compose start`。不得把不同时间点的两个卷混用，也不能只复制写入中的 `.db` 而漏掉 WAL。可选 Solver 无持久数据，无需另存模型探测状态。

## 模型刷新与动态记录

默认同步不会重复已经完成或中断的一次性网关模型请求。自动站点的「刷新模型列表」需要再次确认，随后排入独立任务；同一刷新任务的传输重试不会重复重置探测状态。刷新可能创建临时 Key 和发起上游请求，应先阅读确认框。旧 Key 未清理时保留其清理资料，仅阻止对应分组的新探测。

模型详情和费用比较分别展示模型采集时间与报价时间。一次性快照缺少采集时间，或模型快照超过三个配置同步周期时，提示模型列表较旧或时间未知；新的分组、报价同步不会把旧模型快照标成新数据。提示不会自动发起模型探测，也不代表已验证实际推理可用性。

动态记录保留最多 2000 条，并支持按站点、分组及明细搜索和分页。除倍率变化外，双方清单均已知时会报告模型增删；公开模型价格的输入、输出、缓存、按次和计费表达式变化也会记录。未知清单变成已知清单不会被误报为模型上架。

## 管理 API

路径前缀为 `<随机管理入口>/api`，均需管理 Cookie。导出使用 POST，不能从未鉴权的前台下载明文凭据。

| 方法与路径                                 | 请求 / 响应                                                           |
| ------------------------------------------ | --------------------------------------------------------------------- |
| `GET /settings`                            | `{ "sync_interval_seconds": 900, "payment_presets": ["云猫寄售", "链动小铺", "站点直充"] }` |
| `PUT /settings`                            | 支持局部更新 `sync_interval_seconds` 或 `payment_presets`，返回保存后的设置；无效输入不会部分写入 |
| `POST /data/export?format=json`            | 附件下载 JSON，SQLite 使用 `format=sqlite`                            |
| `POST /data/import?format=json&mode=merge` | 文件原始字节，返回 `{ "imported": 3, "removed": 0, "interval": 120 }` |
| `POST /data/export?format=json&cache=omit` | 排除可重新获取的图片缓存；自动降级时返回 `X-Cerium-Backup-Cache: omitted` |
| `POST /data/recovery/export`              | 下载包含 Web 和 Go 持久状态的 gzip 完整恢复包 |
| `POST /data/recovery/import`              | 上传 `application/gzip`，整体替换双库业务状态 |
| `GET /changes?limit=50&offset=0&q=...`     | `{ "changes": [], "total": 0, "offset": 0, "limit": 50 }` |
| `PUT /sites/:id`                          | JSON 必须包含读取时的 `revision`；缺少返回 428，冲突返回 409 |
| `POST /sites/:id/models/refresh`          | `{ "confirmed": true }`；存在活动任务时返回 409 |

JSON 导入使用 `Content-Type: application/json`；SQLite 使用 `application/vnd.sqlite3` 或 `application/octet-stream`。`mode` 支持 `merge` / `replace`，默认合并。所有 PUT / POST 请求须携带匹配的 `Origin` 和 `X-Cerium-Admin: 1`。
